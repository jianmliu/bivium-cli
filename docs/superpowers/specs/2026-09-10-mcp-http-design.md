# Remote MCP over Cloudflare

The user requested HTTP transport and deployment using the existing Cloudflare account. Add an authenticated Streamable HTTP endpoint at `/mcp` while retaining stdio. Reuse the 21 existing tools and their unsigned preparation logic; HTTP deployments do not sign, broadcast or enable relayer publication. Deploy a separate `bivium-mcp` Worker to the existing account so the Pages frontend and keeper are unaffected.

Use the existing protocol revision 2025-06-18: POST JSON requests receive JSON responses, notifications receive 202, GET returns 405 (no standalone SSE), and DELETE terminates the MCP session. Initialize issues a cryptographically random session ID. Every subsequent request requires the same token and session; expired/evicted sessions return 404 and the caller must initialize and preview again. Separate core/action/preview stores per session prevent preview IDs crossing sessions. An in-memory Durable Object coordinator keeps requests on the same isolate; its state may be evicted, so loss always fails closed rather than reconstructing stale previews.

A configured Bearer token is required for `/mcp`; fail closed if missing or invalid. The endpoint supports clients that can supply an Authorization header, not automatic OAuth login. Origins are checked against an explicit allowlist plus the endpoint origin. Local Node HTTP binds loopback by default and validates Host. Bound body bytes (1 MiB), body read time, sessions (32), session idle lifetime (15 minutes), in-flight calls (8), and request rate. Explicit cancellation propagates to existing tool deadlines; client disconnection alone is not interpreted as cancellation.

Cloudflare uses `nodejs_compat`, a bundled validated testnet profile and the existing conservative policy under ID `conservative`. No mock-token risk override or wallet key is deployed. Schema validators are compiled ahead of time with Ajv standalone generation, because Workers prohibit runtime code generation. A host-only registry compiler injection shares tool definitions without changing Node validation defaults.

Validation includes HTTP unit tests, cross-session preview isolation, auth/origin/body/session/cancellation boundaries, official MCP TypeScript client handshake/tools/call, real local Workers runtime, all existing tests and typecheck, deployment dry run, and authenticated live smoke tests. Deployment secret is generated locally with mode 0600 and uploaded through stdin; it never appears in git or chat. Publish the actual URL and a local connection file after verification.
