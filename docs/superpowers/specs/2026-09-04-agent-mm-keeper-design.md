# 用户 Agent 的 MM 与 Keeper 有界自动运行设计

状态：设计评审稿，尚未实现或部署。用户已确认需要在明确授权后持续自动签名运行。

## 目标与范围

在 Bivium Skill 中增加“帮我做市”和“帮我运行结算 keeper”两个运营入口。
用户表达目标和可承担的预算，Agent 发现市场、解释风险、生成可审阅的运行授权，
用户确认后由其控制的执行器持续执行。普通交易继续逐笔签名；自动运行是单独、限时、可撤回的授权。

只支持 Robinhood Chain 测试网 46630。Core 不改动，不加入管理员、资产白名单或升级机制。
不部署共享托管平台，不操作现有官方 Worker，不迁移现有运营资金或密钥。
新增代码、Skill 与测试经 PR 交付；安装、提供密钥、注资、启用线上任务分别需要用户的实际操作授权。

## 已核对的实现

- `bivium-cli` 基线 `6ee3978`：Skill、单次挂单、撤单、预览和结算命令。
- `bivium-mm` 基线 `f898322`：同一 cron/manual 入口运行 quoting、taker、self-arm、keeper 四个 pass。
- 最新 MM 的 ask backing 包含已有 credit 与抵押品支持的新债，不能把所有卖单描述成出售已有持仓。
- 库存限制与单轮报价规模不是持久化的用户授权预算，也不能覆盖旧报价、并发轮次和重复启动。
- `MM_ENABLED` 不会停止 cron 后续的 self-arm/keeper；旧健康状态也只描述 MM。新 session 不复用这一开关作为全局停机。
- Keeper 已有闪电资金路线和模拟；配置了闪电路线但全部失败时不会转为钱包垫付。
- 独立 `bivium-keeper` 仓库当前为 Sepolia BTC vault 业务，不作为本设计的 Robinhood 到期 keeper。

## 方案比较与选择

1. **推荐：复用定价/结算代码，新增独立、有界的用户 session 执行入口。** 不调用四合一旧入口，不改变现有运营部署。
2. 仅增加 Skill 说明并配置旧 Worker：改动少，但无法承诺完整的角色隔离、到期和预算约束，不足以满足目标。
3. 新增链上 session-key/智能账户权限模块：能提供更强的签名权限限制，但涉及新的合约集成和审计，超出本次测试网首版。

## 用户体验

共用“目标 → 发现 → 必要追问 → 预演 → 明确授权 → 运行 → 状态/停止”。
不要求用户理解 tick、ratifier、pool key 或 JSON。

做市需要确认：市场/币种、可用资金和最大敞口、报价偏好、运行期限、Gas 预算。
Keeper 需要确认：服务市场、最低预期净收益、Gas 预算、运行期限。
参数可由 Agent 根据实测数据提出，但必须列入授权摘要，不能把沉默当同意。

确认页突出：哪个账户、做什么、最多用哪些币多少、运行到何时、何时停止、停止后什么还会继续存在。
同时提供完整机器可读授权供核验；授权变更、续期、提高预算和增加市场需要新的确认。
仅讨论策略、确认风险偏好或点击普通交易确认，不构成自动运行授权。

## 首版角色边界

### MM：库存支持的做市

- bid 使用用户事先配置并注入的对应市场资金；ask 仅使用已持有的 DCN credit。
- 在新入口显式禁用抵押品支持的 ask 新债、主动吃单、self-arm、自动充值、mock mint、跨市场转移和自动展期。
- 没有 ask 库存就报告单边做市，不能借款或制造对手成交补库存。
- 利润来源是实际成交与最终结算结果；未成交不产生利息，未实现收益不是已赚到的现金。
- Meme 抵押交付、库存集中、价格骤变和无法卖出风险保留。库存约束不等于保本或可保证的止损。
- 即使只允许 credit ask，也必须核对实际部署的 Core/ABI 和仓位状态；不能用历史“ask 绝不建债”假设代替验证。

### Keeper：已授权仓位的到期辅助结算

- 只服务所选市场中仍有效授权、存在债务且处于允许时间窗口的仓位；不是价格清算机器人。
- 首版只支持明确选定且可验证的原子闪电资金路线；无路线、模拟失败或不满足利润条件则跳过。
- 不默认允许本金垫付，不替借款人新增授权，不夹带 MM、taker 或 self-arm。
- 显式设置正的链上最低回收盈余；预期净收益另扣本轮最大 Gas 成本、兑换费用及安全余量。
- 收益门槛不是获利保证。失败/竞争落败的交易可能损耗 Gas，闪电资金也不等于零成本。

## 自动授权与签名边界

授权绑定：版本/session ID、用户控制的专用执行账户、角色、链与 Core、完整市场标识集合、
允许的操作与目标合约、接收账户、开始与截止时间、风险接受记录、逐币预算、Gas 上限、执行频率和停机条件。

每个角色使用独立专用账户和执行实例；不得复用用户主钱包、官方运营钱包或其它 session 的账户。
密钥由用户在自己的运行环境通过秘密存储提供，Agent 不获取或输出原始密钥。
授权确认与密钥保管是两件事：确认不能自动授予对现有钱包的访问权。

**安全承诺的边界：** 首版使用专用 EOA，不是链上受限 session key。
市场、期限和预算检查由可信执行器强制执行；若主机/执行器/密钥失陷，这些规则不能限制攻击者直接签名。
专用账户、有限注资、无无限额度授权可缩小影响，但不是硬件或合约级权限隔离。
不得在 Skill 中声称“该密钥从密码学上只能执行这两个策略”。

## 预算、报价与持久化状态

- 预算用 token 地址和最小单位整数定义。金额转换使用已验证 decimals，不用浮点美元金额作为硬限制。
- 分开记录资金/信用敞口限额、累计成交限额和累计 Gas 支出。利润或外部转入不自动增加授权预算。
- 使用保守的总敞口计算，不跨行权价/期限用债务抵消 credit 来释放预算。完整市场集合固定在授权里，不跟随 builtin 表新增市场。
- MM 汇总仍有效的已签报价、未确认撤单、已成交信用敞口及本轮拟签报价；跨市场按同一 token 汇总。
- 不依赖 relayer 删除等同取消。签过但发布结果未知的报价也算可能有效，必须登记并占用额度。
- 每个报价 expiry 不晚于 session 截止时间和该操作的市场时间边界。
- 首版允许降低改价频率换取可靠性：旧报价未确认失效或到期前，继续预留其额度；不能把新签报价当作已撤旧单。
- 预算预留先持久化，再签名/广播。无法恢复日志或对账时停止，不通过重启清零预算。
- 每个 session 单写入者，定时和手动触发共用串行入口；使用持久化状态和可恢复的执行记录，禁止重叠轮次。
- 交易绑定 nonce/hash，广播结果不明时先对账；禁止盲目再发。Gas 按签名前的保守上限预留，确认后按实际值核销。
- 对行情设置明确来源与最大陈旧时间；缺失/过期则不产生新敞口。旧报价的有效性与撤销结果独立报告。

## 状态与停机

状态：`draft → approved → running → stopping → stopped`，异常进入 `paused`，到期进入 `expired`。
状态名描述执行器，不描述用户经济敞口已归零。

停止新签名/新广播的条件：用户撤回、授权到期、预算不足、链/合约/账户不匹配、
风险政策拒绝、关键证据过期、状态无法对账、执行记录失效、重复失败达到已授权阈值。
无机会或预计收益不足是本轮跳过，不应被说成系统故障。

“停止”默认停止新增操作并报告仍有效的报价、在途交易、已成交仓位。
若用户在初始授权中明确包含撤单及其预留 Gas，可执行该范围内的撤单；否则另行请求签名。
全局签名禁用后不再自动发送任何交易。离线机器无法保证即时撤单，只能依赖报价截止时间和用户独立撤销。
已广播交易可能在停止/到期之后被打包；不能保证撤回在途交易。Keeper 不保证每个仓位被执行。

到期不自动还款、卖币、领取或展期。遗留仓位及资金后续处理由原权限及新的明确指令决定。
停止 MM 不暗示停止另一独立 keeper，停止 keeper 也不撤回借款人已有授权。

## 实施拆分

1. `bivium-mm`：新增授权 schema/校验、角色独立入口、持久化 session 状态、预算预留/对账、报价与交易签名前检查。
2. `bivium-mm`：接入受限 MM 与闪电资金 keeper；预演、启动、查询、停止使用同一状态机；保留现有运营入口不变。
3. `bivium-cli`：Skill 新增按需加载的 MM/keeper 指引和权限确认模板；仅对通过能力探测的执行器开放自动模式。
4. 行为演练与独立审查后分别提交 Draft PR；未部署前明确标注“已实现、未启用”，不报告用户策略正在运行。

## 验收与禁止上线条件

必须测试：未授权/过期/错链拒绝；MM 不触发其它 pass；ask 不动用抵押品开债；keeper 不钱包垫付；
多轮报价额度不能重复使用；部分成交/撤单失败/发布失败后额度保守保留；重复触发与重启不绕过限额；
Gas 预留包含在途交易；模拟盈利但扣 Gas 不达标时跳过；未知 nonce/回执不重复广播；
截止时间约束签名与报价；停机正确列出残留敞口；用户确认前不安装/注资/启动。

行为演练覆盖“只做市”“只 keeper”“两者都跑”“不准动本金”“亏损/支出达到限额就停”“马上停止”。
任何不能由执行器验证的强保证必须从产品承诺中删除或阻止启动，不能仅由 Skill 提醒替代。

## 自审

- Core 的无管理/无许可与用户执行器的私有风险规则分离；没有新增协议管控。
- 明确区分 EOA 保管、软件执行限制和链上权限；没有伪称 session key。
- 默认角色选择不扩大至借款、taker、自动注资或钱包垫付。
- 区分停止执行器、订单失效、交易确认和经济敞口退出；没有承诺立即平仓。
- 新入口不复用官方密钥或修改官方部署；实施审批不等于上线运行授权。

独立源码检查已完成，核对 `origin/main` 而非陈旧本地 checkout。其发现的四合一入口、
MM 开关覆盖不全、旧报价重叠、库存限制非硬预算、过期行情被接受、共享全权 EOA、
无限/永久授权和缺少累计 Gas/并发控制，均纳入新入口边界。旧入口本身的其它问题不夹带修复。
